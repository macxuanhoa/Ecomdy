# Ecomdy User Guide

**State:** Proposed workflow guide only. There is no Ecomdy application or usable product interface in this repository.

## Intended users

The proposed direct users are Ecomdy Marketing / Content Team members. Vietnamese cross-border sellers are the intended beneficiaries; this guide does not claim validated user research.

## Target workflow

1. A source administrator reviews the source's public status, terms, access method, rate limits, attribution, and retention before enabling it.
2. A team member opens the weekly digest and checks its date range, source links, source dates, conflicts, and evidence status.
3. The editor opens a digest item to inspect its underlying source versions, claims, and evidence. Unsupported or unresolved claims remain clearly marked and should not be repeated as facts.
4. The editor creates website, social, or short-form video drafts from eligible evidence. Each claim and figure retains its citations.
5. The editor checks factual accuracy, relevance, language, brand guidance, and channel format; edits create a new version.
6. An authorized reviewer approves the exact content version. Any later change returns the content to review. Publication remains a human-controlled step outside this proposed workflow.
7. For freshness findings, the editor checks the authorized article, flagged claim, newer evidence, and effective dates before deciding whether to revise.

## Safe handling

- Treat external source text and generated text as untrusted input.
- Do not add private source lists, brand assets, unpublished content, credentials, or customer data to public repositories or provider prompts without authorization and policy review.
- Do not treat a link as proof by itself; verify that evidence supports the associated claim.
- Escalate conflicting regulatory, tax, shipping, fee, or numerical claims for human review.

## Availability and limitations

The current repository provides documentation and a local advisory DevHarness. There are no product login, digest, content editor, approval, freshness-audit, or publishing screens to operate. See [Developer Onboarding](developer-onboarding.md) for repository checks and [Project Context](project-context.md) for the current product state.
